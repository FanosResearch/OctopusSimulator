# Link implied: w=4 (a_mask has 4 bits: 0xf, 0x3), level TL-UL, every message single-beat; sizes not
# drawn (the scenario uses size 2 = 4 bytes so that mask 0xf is the full beat). Name: L0.
# Four "//" breaks, in the drawn cycles 4, 8, 12, 16; each counted as one cycle. a_ready, d_ready HIGH
# from c1 on; every beat accepted. Every response is drawn ONE cycle after its request, which is
# exactly the simulator's minimum latency: no +1 variant is needed.
# Cycle convention as in fig06.txt.
# Messages (caption: PutFullData writes 0xabcd; Get reads 0xabcd; PutFullData writes 0x0000;
# PutPartialData writes part of 0xffff; Get reads 0x00ff):
#   c1  PutFullData    address 0x0 mask 0xf data 0xab  -> c2  AccessAck
#   c5  Get            address 0x0 mask 0xf            -> c6  AccessAckData data 0xab
#   c9  PutFullData    address 0x0 mask 0xf data 0x0   -> c10 AccessAck
#   c13 PutPartialData address 0x0 mask 0x3 data 0xf   -> c14 AccessAck
#   c17 Get            address 0x0 mask 0xf            -> c18 AccessAckData data 0x3
# DATA NOTE (flagged): the drawn data values are schematic. They do not agree with the caption (0xab vs
# 0xabcd, 0x3 vs 0x00ff) and no byte interpretation makes the last Get return 0x3 after a
# PutPartialData of 0xf under mask 0x3 on a zeroed word (a real memory returns 0xf). The waveform table
# keeps the drawn values; the expected transcript carries the A-channel data as driven by the scripted
# master (the drawn values) and, for the last Get, the value a real memory returns (0xf) with the drawn
# 0x3 noted. Data values are the little-endian word of the active lanes.
