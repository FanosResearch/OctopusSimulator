# Link implied: w=16, level TL-UH (a 2-beat burst), z>=3, a>=8. Name: L0. a_ready is HIGH from c1 on.
# Cycle convention as in fig06.txt. Six PutFullData messages, every beat accepted:
#   c1,c2  size 5 (32 B) address 0x40: beat 0 lanes 0..15 = bytes 0x40..0x4f, beat 1 = 0x50..0x5f
#   c4     size 4 (16 B) address 0x10: lanes 0..15 = 0x10..0x1f
#   c6     size 3 (8 B)  address 0x58: lanes 8..15 = 0x58..0x5f (inactive lanes 0..7 crossed out)
#   c8     size 2 (4 B)  address 0x24: lanes 4..7 = 0x24..0x27
#   c10    size 1 (2 B)  address 0x76: lanes 6, 7 = 0x76, 0x77
#   c12    size 0 (1 B)  address 0xc1: lane 1 = 0xc1
# The byte in a lane equals the low byte of that lane's address, which is the figure's device.
# Data notation in this file: the w lanes in order, lane 0 first, two hex digits per lane, `..` for an
# inactive lane. mask is NOT drawn; it is derived by §4.5 (PutFullData: all active lanes HIGH) and the
# comparator may check it (the monitor enforces it anyway, M-MASK-1/2).
# The address column is the wire address, constant across the burst; beat 1 of the first message carries
# the bytes at 0x50 = 0x40 + 1*16 (plan §1.4 effective address, not a wire field).
